# 简历优化：安装、使用与来源

这是 [Tw93/Kami](https://github.com/tw93/Kami) 的正式 fork，由 [LongJingSU](https://github.com/LongJingSU) 维护简历优化增强部分。不是从零原创的排版引擎，也不是上游官方版本。

## 安装

在支持 Agent Skills 的工具中选择本仓库的 `resume-optimizer` 技能。

```bash
npx skills add LongJingSU/resume-optimizer --skill resume-optimizer
```

内容优化不需要特定依赖。需要 Kami 的排版模板和 PDF 工具时，可再安装同仓库的 `kami`：

```bash
npx skills add LongJingSU/resume-optimizer --skill kami
```

也可将 `skills/resume-optimizer/` 整个文件夹复制到宿主支持的技能目录。只复制 `SKILL.md` 会遗漏引用的内容与排版规则。安装位置以所用工具为准。

## 使用

给出已有简历、项目材料、岗位方向或 JD，以及页数要求。例如：

> 使用 $resume-optimizer，把我的简历整理为面向 AI 应用交付岗位的一页版。按公司和服务团队展开项目，写清问题、个人职责、方案和成果。保留正文可读性，作品链接需要明确标注并可点击。

已有认可版本时，直接提出局部修改，例如“项目间距拉开，内容不要再删”“调整工具顺序”“这项培训只完成首轮”。技能会按修改范围处理，不默认全篇重写。

## 本分支增加了什么

- 基本信息与教育摘要前置，年龄和学历性质按用户提供的信息展示。
- 按公司、服务团队、项目组织经历，避免不同雇主和个人实践混在一起。
- 保留业务问题、个人职责、关键方案和结果，避免为凑一页压成口号。
- 区分意向、洽谈、验证、首轮交付与长期使用；不把工具支持包装成企业转型。
- 区分单篇与累计阅读、课程收益与利润，不用传播数据冒充销售结果。
- 一页排版以可读性为前提，增加公司、项目、板块之间的视觉间隔。
- 清晰标注主页与作品入口，检查导出 PDF 的实际链接。
- 局部修改保留已确认内容，最终核对内容覆盖、页数、字体和渲染图。

这些规则由多轮真实简历优化中出现的问题提炼而成；示例已泛化，仓库不包含该次求职者的简历、联系方式、客户信息或收益明细。

## 维护与验证

规则入口在 `skills/resume-optimizer/SKILL.md`，详细内容与排版规则位于其 `references/`。修改内容规则后，用真实但去标识的情境检查：事实冲突能否被识别、项目是否被过度压缩、用户的页数与工具顺序是否被遵守。

不要把个人成品、浏览器目录或工作区整体提交到本仓库。本分支仅发布可复用规则。原上游的 `dist/kami.zip` 打包流程仅包含 `skills/kami/`；新增简历技能通过上述技能目录安装，不冒称包含在 Kami 的旧发布包中。
