# 事实与内容规则

## 信息不完整与冲突

先读现有材料，再补问。对每条待写经历记录公司或客户、服务团队、个人职责、方案、状态、结果与来源。这个清单用于内部核对，不要求用户填一张冗长表格。

| 已确认事实 | 可写表达 | 不能直接推导 |
|---|---|---|
| 报价、需求访谈，未交付 | 培训需求沟通、方案筹备 | 完成企业内训 |
| 已交付首轮培训 | 独立承接并完成首轮培训 | 完成整个长期培训项目 |
| 给负责人答疑并协助部署 | AI 工具选型、部署与使用支持 | 企业 AI 转型咨询 |
| 产品通过内部验证后中止 | 完成搭建与内部验证，注明中止原因 | 长期上线、持续业务收益 |
| 累计搭建多个 Agent | 累计搭建数量及覆盖场景 | 全部在生产环境稳定运行 |
| 单篇文章阅读量 | 单篇阅读量及确认的数值 | 全账号累计阅读或成交结果 |
| 售卖课程获得收入 | 累计变现或销售收入 | 净利润、年收入或企业项目收入 |

冲突由用户确认后更新，不能永久保留旧结论。例如“之前没谈成、现在首轮完成”允许写新的交付进展，但不要自行补齐未确认的培训人数、课程主题和效果。

## 首屏与教育

首屏通常包括姓名、求职方向、联系方式、期望工作地，以及与筛选相关的教育摘要。用户明确要求时可加入已提供的年龄、学历性质；缺失时不推算。教育摘要可包含学校、专业、学历、年份，详细奖励和成绩按相关性决定是否展开。

证书集中放在末尾。关键证书可在教育摘要简短出现，但不应占据首屏大部分空间。多行认证列表应让第二行与第一项证书对齐，而不是对齐“专业认证”标签。

指标卡是可选项。首屏不要被某个项目的效率数据占满；综合背景可用课程、交付、知识库经验等已证实的能力概括，没有足够事实就不放指标卡。

## 公司 → 团队 → 项目

公司抬头包含名称、日期与实际角色。用一致的浅色抬头、字号或留白区分不同公司。公司内部按团队或场景命名项目，使读者能看出改造的是哪一段业务。

重点项目可以采用两段：

1. **结果**：明确服务团队的使用状态、产出或投入变化，说明比较基线。
2. **问题与行动**：交代为什么需要做、自己负责什么、关键方案及如何融入业务。

也可采用“背景 / 职责 / 结果”短行，选择更易读的形式。不强制每个项目完全同长。工具与功能只保留解释业务方案所需的部分。

假设示例，仅用于演示结构，数字不可套入真实简历：

> **内容团队｜素材检索助手**
>
> 每次检索从约 30 分钟缩短至约 10 分钟，已被编导用于日常找素材。
>
> 针对历史素材无法按内容查找的问题，负责需求梳理与应用开发；建立带时间点的字幕索引，串联检索、片段预览和人工确认，融入已有制作流程。

不能压成“开发检索助手，效率提升”。也不能把减少某一步的耗时写成全流程或全公司效率提升。

## 营销、课程与培训

- 社媒经历描述内容生产和传播结果；没有线索与销售证据时，不写已完成获客转化。
- 课程可以写成熟课程数量、主题、对外售卖、已确认收益及开发到销售的流程。只有实际跑通才用“完成变现”。
- 企业培训区分接洽、备课、首轮交付、完整交付和复购。“从 0 到 1 独立承接”需要用户确认承接与职责，不意味着所有轮次都已结束。
- 个人社媒不应混入某家公司的任职成果。客户培训若归属不明确，先作为独立实践，不擅自归给雇主。

## 精简的边界

优先去掉重复指标、反复出现的工具名、空泛自评、不相关经历和过长的公司简介。保留核心业务问题、本人贡献、关键机制和真实结果。

不使用“每条只能 6-20 字”这样的机械限制。内容简短但无法理解责任和价值，仍是不合格。用户认为内容太少时，回到原始材料补足信息，不靠形容词扩充。
