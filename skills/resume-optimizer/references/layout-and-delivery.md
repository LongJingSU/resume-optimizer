# 排版与验收

## 页数与模板

用户给出的页数优先。没有要求时依据经历量与投递场景选择一至两页，不强制所有人一页，也不为满足模板默认两页而填充内容。

已有认可的风格就沿用。Kami 的标准简历模板和部分检查使用两页约定；用户要求一页时，在简历副本上调整，使用实际页数检查，不把两页专用平衡检查的失败当作内容缺失，更不能谎称它通过。

## 阅读节奏

可从下表作为中文 A4 一页简历的试排起点；它不是任何字体和内容都适用的固定配置。

| 元素 | 起点 | 调整目标 |
|---|---|---|
| 正文 | 10.5-11 pt，行距约 1.45-1.55 | 无需放大屏幕也能连续阅读 |
| 公司抬头 | 11.5-12 pt，浅底色或较强字重 | 不同公司的任职边界一眼可见 |
| 团队 / 项目标题 | 约 11 pt | 与正文区分，不争抢公司层级 |
| 公司内相邻项目 | 约 4-5 mm 的可见间隔 | 不连成一堵文字墙 |
| 大板块之间 | 约 5-7 mm | 尤其社媒链接到核心能力之间要留出空隙 |
| 日期、辅助说明、证书 | 约 9-9.5 pt | 不与正文争抢注意力，仍保持可读 |

必要时给相邻项目加细而浅的分隔线；不要同时堆叠边框、色块、粗线与强调色。使用一种主强调色，只突出少量关键成果。

用户说“底部有空白，正文放大一点”时，先检查真实底部空间，增加字号、行距和项目间距后重新导出。用户说“太拥挤”时，优先改善对应块的间隔；不要缩小全篇来满足一页。

增加内容造成溢出时，依次尝试：删重复表达、合并辅助信息行、调整局部几何与合理页边。不要裁掉文本、压成极小字号或取消用户刚认可的项目留白。必要时说明一页与可读性的实际冲突，由用户选择。

## 作品与主页入口

- 只放用户选择的入口；已删除的 GitHub 等入口不自动恢复。
- 标签明确说明目的，例如“X 主页（点击跳转）”“小红书主页｜账号名（点击跳转）”“飞书项目集（点击跳转）”。账户名和 URL 使用用户提供的值。
- 不把冗长 URL 铺满正文，不仅显示一个陌生账号名让招聘者猜。
- 在 HTML 和最终 PDF 中都保留真实链接。检查注释中的 URI 与相应标签是否匹配；不要为测试而发送消息或更改链接页面。

## 迭代时保留什么

修正前确认当前版本和用户指定区域。保持已确认的事实、公司归属、日期、工具顺序、课程收益与交付状态；局部间距修改不应触发全篇重写。无法定位“这部分”时，结合截图和最近修改判断，仍有歧义再简短询问。

可编辑源、正文稿和 PDF 同步更新，保留上一认可版本便于回退。临时脚本不应硬编码成公共模板中的姓名、电话、项目成果或本机目录。

## 最终验收

1. **事实与覆盖**：核对保留字段、数字、约数、项目归属和最新澄清；不要只验证 HTML 存在文字，PDF 也要有。
2. **页面**：检查真实页数、裁切、重叠、断行、孤立标题、证书缩进和末页边界。
3. **视觉**：查看最终版本每页渲染图，公司与团队层级清晰，板块间有实际留白。静态检查不能代替这一步。
4. **链接**：核对数量、目标和文字标签；区分本地链接存在与远端访问权限，不因没有权限而虚报可公开访问。
5. **交付**：提供最终文件和必要的可编辑源，简短说明变更及仍待核实的事项。

有现成 PDF 工具时用它检查，不要求安装某个特定工具。只有文本稿时明确标注未完成 PDF 排版检查。修改小而可逆时做针对性检查即可，不必每轮重复整套招聘评估。
