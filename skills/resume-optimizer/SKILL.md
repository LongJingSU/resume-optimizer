# 简历优化

把候选人的真实贡献写清楚，让招聘者快速理解其背景、服务对象、具体工作和结果。优先保留已确认的内容与风格，按当前反馈修改。

## 先判断修改范围

- **新写或大改**：确认目标岗位、受众、页数与格式，从已有材料提取事实，再组织内容。已有信息足够就继续，不要求用户重复提供 JD 或经历。
- **内容修订**：只更新受影响的事实、文案和相关摘要；不重新编排全篇，除非新内容出现排版问题。
- **视觉修订**：保留已认可的文案、字号与项目范围，先调整对应的间距、层级和分页。用户说“太密”不等于授权删掉项目说明。

初次结构优化或出现事实冲突时，读 [事实与内容规则](references/content-rules.md)。制作 PDF、控制一页或调整版式时，读 [排版与验收](references/layout-and-delivery.md)。

## 工作顺序

1. **目标**：从 JD 或用户表述提炼核心能力。通用求职版使用岗位方向，不绑死某一家招聘公司。缺少 JD 时可以沿已明确的职业方向继续，不编造招聘要求。
2. **事实**：区分已交付、内部验证、洽谈中、意向和中止。原稿与后续说法冲突时，只询问影响表述的具体事实；等待期间继续修改无关部分。
3. **组织**：工作经历通常按公司逆序排列，公司内按服务团队或业务场景展开项目。项目相关度决定篇幅和内部顺序，不应破坏任职归属。
4. **表达**：每个重点项目让人读懂“服务谁、什么问题、本人做什么、如何实现、结果如何”。结果可前置，但不可只留一个工具名和一项指标。
5. **排版与交付**：尊重页数约定。保留清晰的公司、团队、正文三级层级；核对最终导出的内容、页数与链接，并逐页看渲染图。

## 关键边界

- 量化要保留单位、周期、约数、比较基线和统计口径。没有数字可以写已验证的使用状态或可核对的交付物，不补造百分比。
- 首屏交代基本背景与定位；用户提供并要求展示的年龄、学历、工作地点可放这里。不要从毕业年份推算年龄，也不要自行升级学历性质。
- 公司名、任职时间与职责归属要清晰。兼任产品与应用开发可以据实呈现，不自动升级成全栈工程师或企业转型顾问。
- 社媒、课程、企业培训可作为营销或交付能力的证据，但阅读、粉丝、收入和咨询意向是不同结果。
- 工具顺序优先遵从用户要求，否则按目标岗位与真实熟练程度排列。不要把工具列表当成项目证据。
- 当前修改要求优先于模板默认页数、固定指标卡和固定标签。中文项目标签需要时使用“背景、职责、结果”等清晰表达。

## 输出

默认给出可直接使用的简历正文；需要文件时保留可编辑源文件并交付最终文件。简短说明变化，无需每次附长篇方法论报告。小幅迭代无需重新开展全套评估。

本技能的内容方法不依赖特定渲染器。环境提供 Kami 时，可用其模板、字体与 PDF 工具；未安装时，使用现有文档工具，或交付完整 Markdown，不声称已经生成或检查 PDF。
